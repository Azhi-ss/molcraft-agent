## 1. 改动内容

### 改动前（5字段简单模板）

```
假设ID | 瓶颈 | 文献支撑 | 改进方案 | 验证指标
```

**问题：**
- 没有推理过程，无法知道 Agent 是怎么得出假设的
- 置信度不透明，哪些环节可能错了
- 没有失败预判，验证失败后不知道从哪排查
- 没有最低门槛，"提升就算成功"的心态导致无效改动多

### 改动后（三层结构化假设）

#### 第一层：推理链

| 步骤 | 内容 | 置信度 | 推理方式 | 依据来源 |
|------|------|--------|----------|----------|
| S1 | 基础事实/文献结论 | 高/中/低 | 文献/经验 | 具体出处 |
| S2 | 从 S1 演绎 | 高/中/低 | 演绎/归纳 | 从 Sx |
| S3 | 从 S2 演绎 | 高/中/低 | 演绎/归纳 | 从 Sx |
| S4 | 最终结论 | 高/中/低 | 演绎/归纳 | 从 Sx |

**木桶效应：** 综合置信度 = 所有步骤中最低的那个
**风险标注：** 明确写出「若验证失败，优先排查哪步」

#### 第二层：验证标准

验证前提前约定成败门槛：

- **Q1**：如果核心指标提升 < 5%，是否仍保留？理由？
- **Q2**：如果指标下降，最可能的原因是什么？（分类+理由）
- **Q3**：本假设的最低可接受结果是什么？（量化阈值）

#### 第三层：改进方案

| 改动文件 | 改动内容 | 验证指标 |
|----------|----------|----------|
| 具体路径 | 具体改动 | 可量化的验证方式 |

## 2. 预期效果

### 短期效果
- ✅ 假设提出不再是黑箱，推理过程完全透明
- ✅ 失败时有预判方向，不用从头排查
- ✅ 最低门槛过滤掉明显无效的实验

### 长期效果
- 📈 Agent 迭代质量提升，避免「随机试错」式开发
- 📈 评审时可以清晰看到推理链是否合理
- 📈 积累失败模式，改进诊断能力
